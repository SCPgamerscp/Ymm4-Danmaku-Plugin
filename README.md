# YMM4 用 東方風弾幕作成プラグイン

[YukkuriMovieMaker 4](https://manjubox.net/ymm4/) 上で、東方 Project 風の弾幕を
**タイムラインアイテムとして生成・描画・編集**するためのプラグインです。

外部の弾幕動画を用意することなく、YMM4 のプレビューを見ながら弾幕を組み立て、
キーフレームで発射源を動かし、発射音まで同期させることができます。

## 特徴

### 3 階層の弾幕生成

| 階層 | 方法 | 想定ユーザー |
|:---|:---|:---|
| 第 1 階層 | **プリセット + GUI スライダー** | とりあえず弾幕を出したい人 |
| 第 2 階層 | **物理パラメータの直接調整**（初速・加速・角速度・重力・減衰・ホーミング…） | 思った通りの軌道を作りたい人 |
| 第 3 階層 | **外部データ読み込み**（JSON / BulletML / Lua） | 弾幕を「プログラム」として書きたい人 |

### 描画

- 組み込み **12 種類**の弾形状（丸弾・中弾・大玉・米弾・札弾・鱗弾・星弾・輪弾・光弾・矢弾・蝶弾・粒）
- **ユーザー指定画像**をスプライトとして使用（PNG / JPEG など WIC 対応形式）
- **加算合成（グロー）** による発光表現、グロー強度の多重パス描画
- 色モード: 単色 / グラデーション / 虹色 / パレット / ランダム、色相の連続変化
- **残像（トレイル）** — 長さ・間隔・減衰・縮小率を個別指定
- フェードイン / フェードアウト、スケール変化、回転、進行方向への自動整列
- スプライト単位の **バッチ描画**（`ID2D1CommandList`）と **オブジェクトプーリング** による高速化

### 挙動

- **ホーミング（追尾）** — 旋回速度・持続時間・開始遅延を指定
- **多段分裂** — 世代数・分裂数・拡散角・速度・縮小率・親の消滅を指定（最大 10 世代）
- **当たり判定** と被弾エフェクト（飛沫）
- 画面外の扱い: 消滅 / 反射 / ワープ / 無処理
- パターン 10 種: 全方位 / 扇 / 螺旋 / 自機狙い / 散弾 / 壁 / 花 / 薔薇曲線 / 疑似レーザー / 鞭

### 編集体験

- **キーフレーム対応** — 発射位置 X / Y、ターゲット位置 X / Y
- **プレビュー上のドラッグ**で発射源・ターゲット位置を直接指定
- 複数エミッター（最大 16 個）
- **完全な決定論性** — タイムラインをどこへシークしても、同じシードなら必ず同じ弾幕になる

### 効果音

- 発射 / 変化 / 被弾 / 消滅の 4 種類を YMM4 の設定画面から指定
- **ピッチ微変調** — 同時発射時に音が単調にならないよう ± 半音幅でランダムにずらす
- 毎秒の発音数上限、同時発音のまとめ（飽和防止）
- 映像側と音声側が**同じシードで独立に再シミュレーション**するため、
  レンダリング順に関係なく音ズレが起きない

## インストール

### 方法 A: `.ymme` ファイル（推奨）

1. [Releases](../../releases) から `Ymm4DanmakuPlugin.ymme` をダウンロード
2. ファイルをダブルクリック、または YMM4 のウィンドウへドラッグ＆ドロップ
3. YMM4 を再起動

### 方法 B: 手動配置

DLL を以下のフォルダへ置きます（フォルダ名は任意ですが、DLL 名と揃えるのが無難です）。

```
<YMM4 インストールフォルダ>\user\plugin\Ymm4DanmakuPlugin\Ymm4DanmakuPlugin.dll
```

配置後、YMM4 を再起動してください。

### 確認

タイムラインの追加メニューに **図形アイテム → 東方風弾幕** が現れれば成功です。

## 使い方

### 1. 弾幕アイテムを置く

タイムラインに **図形アイテム** を追加し、図形の種類から **「東方風弾幕」** を選びます。

> [!NOTE]
> 弾幕は「図形アイテム」として実装されています。これは YMM4 の公開拡張点の都合で、
> 機能的にはカスタムアイテムと同等です。詳細は
> [設計上の重要な決定](#設計上の重要な決定) を参照してください。

### 2. プリセットから作る（第 1 階層）

**プリセット** グループのコンボボックスから東方風のサンプルを選び、**［適用］** を押します。

同梱プリセット（10 種）:

| 名前 | 内容 |
|:---|:---|
| 全方位リング | 基本の全方位弾。等間隔の弾を一定周期で放つ |
| 螺旋乱舞 | 発射角を回転させ続ける螺旋弾 |
| 自機狙い扇 | ターゲット方向へ扇状に撃つ |
| 花弁 | 花びらのように広がる装飾弾 |
| 雨弾 | 上空から降り注ぐ重力弾 |
| 追尾蝶 | ゆるやかに追尾する蝶弾 |
| 多段分裂星 | 星弾が数回に分けて分裂する |
| 疑似レーザー扇 | 弾を密に並べてレーザーに見せる |
| 乱れ撃ち | 角度・速度をばらけさせた散弾 |
| 虹輪 | 色相が回り続ける虹色のリング |

適用後は各スライダーで自由に調整できます（プリセットは「初期値」として展開されます）。

> [!TIP]
> プリセット適用は **発射位置 X / Y を上書きしません**。
> 配置はタイムライン上で決めた値が保たれるので、安心して適用できます。

### 3. パラメータを詰める（第 2 階層）

編集エリアは以下のグループに分かれています。

| グループ | 主な項目 |
|:---|:---|
| **全体** | 乱数シード / 最大弾数 / 再生速度 / 計算の細かさ / 画面外の扱い / 効果音チャンネル |
| **エミッター** | 名前 / 有効 / 発射位置 X・Y（キーフレーム可）/ 公転半径・速度・位相 / シードずらし |
| **プリセット** | プリセット選択と保存・読み込み・書き出し |
| **弾幕データ** | 生成方法（パターン / JSON / BulletML / Lua）とその設定 |
| **パターン** | 種類 / 一度に撃つ数 / 段数 / 基準角 / 拡散角 / 発射間隔 / 連射 …|
| **弾の動き** | 初速 / 加速 / 角速度 / 減衰 / 速度上下限 / 重力 / 風 / 寿命 |
| **ホーミング** | 追尾する / 旋回速度 / 持続時間 / 開始遅延 |
| **見た目** | 弾の形 / 画像 / 大きさ / 回転 / 色モード / 色 / 加算合成 / グロー / 不透明度 / フェード |
| **残像** | 残像の数 / 間隔 / 減衰 / 縮小率 |
| **分裂** | 分裂する / 遅延 / 分裂数 / 拡散角 / 速度 / 縮小率 / 親を消す / 世代数 |
| **当たり判定** | 有効 / ターゲット X・Y（キーフレーム可）/ 半径 / 被弾エフェクト |
| **効果音** | 発射音 / 変化音 / 被弾音 / 消滅音 の有効切り替え |

**位置の指定** は 3 通りできます。

1. スライダーに数値を入力
2. キーフレームを打って時間変化させる
3. **プレビュー上の制御点をドラッグ**（丸い点 = 発射源、四角い点 = ターゲット）

### 4. 外部データを読み込む（第 3 階層）

**弾幕データ → 生成方法** を切り替えると、ファイルまたは直接入力したテキストから弾幕を生成できます。

| 生成方法 | 対応拡張子 | 用途 |
|:---|:---|:---|
| パターン | — | GUI スライダーで組む（既定） |
| JSON | `.json` | 時刻付きの発射命令をそのまま列挙 / プリセット形式 |
| BulletML | `.xml` `.bulletml` `.bml` | 既存の BulletML 弾幕定義を流用 |
| Lua | `.lua` | スクリプトで弾幕を組み立てる |

書式は [外部データ形式](#外部データ形式) を参照してください。

### 5. 効果音を鳴らす

効果音は **映像アイテムとは別の「音声エフェクト」** として鳴らします。

1. YMM4 の **設定画面 → 弾幕 → 弾幕効果音** で、発射音 / 変化音 / 被弾音 / 消滅音に
   使う WAV ファイル、音量、ピッチ変調幅、毎秒の上限を指定します
2. 音声アイテム（無音でも可）を弾幕と同じ区間に置きます
3. その音声アイテムに **音声エフェクト → 弾幕 → 弾幕効果音** を追加します
4. 音声エフェクトの **チャンネル** を、弾幕アイテムの **全体 → 効果音チャンネル** と同じ番号にします

これで発射タイミングに合わせて効果音が鳴ります。

> [!NOTE]
> 音声側は映像側の計算結果を参照せず、**同じシードで独立に再シミュレーション**します。
> エンジンが完全に決定論的なので結果は必ず一致し、
> 映像と音声のどちらが先にレンダリングされても音ズレが起きません。

対応形式は **WAV**（PCM 8 / 16 / 24 / 32 bit、IEEE float 32 bit、WAVE_FORMAT_EXTENSIBLE）です。
外部ライブラリに依存しないよう自前でデコードしています。

### 6. 複数エミッター

1 つの弾幕アイテムに最大 **16 個**のエミッターを持たせられます。
それぞれ独立した位置・パターン・見た目を持つので、
「中央から全方位 + 左右から自機狙い」のような複合弾幕を 1 アイテムで作れます。

同じ設定のエミッターを複数置くときは **シードずらし** を変えると、
乱数が別系列になって弾が重なりません。

## 外部データ形式

### JSON — タイムライン形式

時刻付きの発射命令を列挙します。

```json
{
  "version": 1,
  "name": "サンプル弾幕",
  "loopDuration": 4.0,
  "shots": [
    { "time": 0.0, "way": 24, "spread": 360, "speed": 180, "sprite": 0, "color": "#FFFF4060" },
    { "time": 0.5, "way": 8,  "spread": 60, "speed": 260, "aim": true, "sprite": 3 },
    { "time": 1.0, "way": 1,  "speed": 200, "angle": 90, "accel": -80, "angularVelocity": 45 }
  ]
}
```

| キー | 既定値 | 意味 |
|:---|:---|:---|
| `time` | `0` | 発射時刻（秒） |
| `angle` | `0` | 発射角（度。**0 = 右**、反時計回り） |
| `aim` | `false` | `true` ならターゲット方向を基準にする |
| `way` | `1` | 一度に撃つ弾数 |
| `spread` | `360` | 弾を配る角度の幅（度） |
| `speed` | `200` | 初速（px/秒） |
| `accel` | `0` | 加速度（px/秒²） |
| `angularVelocity` | `0` | 角速度（度/秒） |
| `lifetime` | `0` | 寿命（秒。0 なら既定値） |
| `sprite` | `-1` | 弾形状のスロット番号（-1 なら継承） |
| `color` | — | `#AARRGGBB` または `#RRGGBB` |
| `scale` | `1.0` | 大きさ倍率 |
| `offsetX` / `offsetY` | `0` | 発射位置のずらし |
| `sound` | `true` | 発射音を鳴らすか |
| `homing` | — | 追尾するか（省略時はエミッター設定を継承） |

`loopDuration` を指定すると、その周期でスクリプト全体が繰り返されます。

### JSON — プリセット形式

`pattern` / `physics` / `appearance` を持つ形式は、
GUI スライダーの設定と等価な内容として読み込まれます。
プリセットの書き出しファイルがそのまま使えます。

### BulletML

[BulletML](http://www.asahi-net.or.jp/~cs8k-cyu/bulletml/) の主要要素に対応した
ミニ VM を内蔵しています。`<action>`, `<fire>`, `<bullet>`, `<changeDirection>`,
`<changeSpeed>`, `<accel>`, `<vanish>`, `<repeat>`, `<wait>`, 各 `*Ref`、
`$rand` / `$rank` / `$1..$n` などの式が使えます。

```xml
<?xml version="1.0" ?>
<bulletml type="vertical">
  <action label="top">
    <repeat><times>8</times>
      <action>
        <fire>
          <direction type="sequence">45</direction>
          <speed>2</speed>
          <bullet/>
        </fire>
        <wait>5</wait>
      </action>
    </repeat>
  </action>
</bulletml>
```

> [!IMPORTANT]
> BulletML の角度は **0 = 上**、本プラグイン内部は **0 = 右** です。
> 変換は自動で行われるので、既存の BulletML をそのまま持ち込めます。

BulletML の速度単位はフレーム基準（1 = 1px/フレーム）なので、
**弾幕データ → 速度換算** で px/秒 へ読み替えます（既定 `60` = 60fps 相当）。
**難易度($rank)** は `$rank` に渡す値（0.0〜1.0、既定 0.5）です。

**弾幕データ** グループの項目は共通で以下の通りです。

| 項目 | 意味 |
|:---|:---|
| ファイル | 読み込む `.json` / `.xml` / `.lua` のパス |
| 本文 | 直接記述する場合はこちら（**ファイルより優先**） |
| 速度換算 | BulletML の速度 1 を何 px/秒 とみなすか |
| 難易度($rank) | BulletML の `$rank` に渡す値 |
| 繰り返し | スクリプトが終端に達したら最初から再生する |

### Lua

外部ライブラリに依存しない **Lua サブセットインタプリタ**を内蔵しています。
スクリプトは読み込み時に 1 度だけ実行され、結果は時刻付き発射命令の列に展開されます。

```lua
-- 螺旋弾を 4 秒周期で
loop(4.0)

local angle = 0
for i = 1, 120 do
  fire{ angle = angle, speed = 220, way = 3, spread = 20, sprite = 3 }
  angle = angle + 13
  wait(2)          -- 2 フレーム待つ
end
```

利用できる関数・変数:

| 名前 | 意味 |
|:---|:---|
| `fire{ ... }` | 弾を発射。キーは JSON のキー名（`angle` `speed` `way` `spread` `aim` `sprite` `color` `scale` `lifetime` `accel` `turn` `offsetx` `offsety` `sound` `homing`） |
| `fire(angle, speed)` | 簡易記法 |
| `wait(frames)` / `waitsec(seconds)` | 時刻を進める |
| `time()` / `settime(seconds)` | 現在時刻の取得・設定 |
| `loop(seconds)` | スクリプト全体のループ周期 |
| `rand()` / `randrange(min, max)` | 決定論的乱数 |
| `fps` | 1 秒あたりのフレーム数（60） |
| `math.*`, `string.format`, `table.insert`, `print`, `tostring`, `tonumber`, `type` | 安全な標準関数のみ |

> [!WARNING]
> `io` / `os` / `require` などのファイル・OS アクセス系は**意図的に未実装**です。
> 実行ステップ数にも上限（500 万ステップ）があり、無限ループでは YMM4 が固まりません。
> 生成できる発射命令は 200,000 件までです。

## プリセット

### 操作

編集エリアの **プリセット** グループから操作します。

| ボタン | 動作 |
|:---|:---|
| 適用 | 選択中のプリセットをこのエミッターへ展開する |
| 更新 | プリセットフォルダを読み直す |
| 保存 | 現在の設定をプリセットフォルダへ `.json` として保存する |
| 読み込み… | 任意の `.json` を読み込んで適用し、フォルダへコピーする |
| 書き出し… | 現在の設定を任意の場所へ `.json` として書き出す |
| サンプル出力 | 同梱の東方風サンプル集をフォルダへ書き出す（編集の下敷きに便利） |

### 保存フォルダ

既定は以下です。**設定画面 → 弾幕 → 弾幕効果音 → プリセット → 保存フォルダ** で変更できます。

```
%AppData%\YukkuriMovieMaker\DanmakuPresets
```

- 一覧は「同梱プリセット + フォルダ内の `.json`」を統合したものです
- **同名なら フォルダ側が優先**されます。同梱サンプルと同じ名前で保存すれば内容を差し替えられます
- 壊れた `.json` があってもその 1 件だけスキップし、エラー内容を編集エリアに表示します

## ビルド方法

### 通常のビルド（Windows + YMM4 あり）

YMM4 のインストール先を教える必要があります。

```powershell
# 1. サンプルをコピーして自分の環境に合わせる
Copy-Item Directory.Build.props.sample Directory.Build.props
notepad Directory.Build.props     # YMM4DirPath を書き換える

# 2. ビルド
dotnet build src/Ymm4DanmakuPlugin/Ymm4DanmakuPlugin.csproj -c Release
```

`CopyToYMM4PluginDir` が `true` なら、ビルド後に
`<YMM4>\user\plugin\Ymm4DanmakuPlugin\` へ自動コピーされます。

`Directory.Build.props` は環境依存のため **`.gitignore` 済み**です。コミットしないでください。

### スタブ SDK でのビルド（Windows 以外 / CI）

YMM4 の DLL は再配布できないため、CI や Linux 上では
`build/ymm4-stubs/` にある **API スタブ**を参照してコンパイル検証します。

```bash
dotnet build src/Ymm4DanmakuPlugin/Ymm4DanmakuPlugin.csproj -p:UseYmm4Stubs=true
```

> [!WARNING]
> スタブは**シグネチャだけを模した空実装**です。コンパイルが通ることの確認専用で、
> これで出力した DLL は YMM4 では動作しません。
> スタブビルド時は YMM4 へのコピーも行われません。

### ユニットテスト

コアエンジンは YMM4 / WPF / Direct2D に一切依存しないので、
Windows 以外でもそのままテストできます。

```bash
dotnet test tests/Ymm4DanmakuPlugin.Core.Tests/Ymm4DanmakuPlugin.Core.Tests.csproj
```

現在 **429 件** のテストが通ります。カバー範囲は開発計画書の検証項目に対応しています。

| テストファイル | 検証内容 |

## 設計上の重要な決定

将来の開発者・AI が同じ結論に再到達できるよう、判断の理由を残します。

### `IVideoItem` ではなく `IShapePlugin` を使う

YMM4 の Plugin SDK に **`IVideoItem` という公開拡張点は存在しません**。
タイムラインに独自の描画物を置く場合、公開されている手段は
`IShapePlugin`（図形プラグイン）です。

`IShapePlugin` → `ShapeParameterBase` → `IShapeSource2` の 3 点セットで実装すると、
タイムライン上では「図形アイテム」として扱われますが、
独自の編集 UI・独自の Direct2D 描画・プレビュー上の制御点をすべて持てるため、
**機能的にはカスタムアイテムと同等**です。

### 効果音は別アイテム + チャンネル方式

映像（図形アイテム）と音声（音声エフェクト）は YMM4 上では別アイテムで、
描画順・レンダリング順も保証されません。
そこで両者を**整数のチャンネル番号**で紐づけ、音声側は映像側の計算結果を参照せず
**同じシード・同じ設定で独立に再シミュレーション**します。

エンジンが完全に決定論的なので発生する効果音イベント列は必ず一致し、
どちらが先に処理されても音ズレが起きません。

### キーフレーム値は設定レコードに入れない

シミュレータは「設定が変わったら作り直す」判定を**設定の署名**で行っています。
キーフレームで毎フレーム変わる値（発射位置・ターゲット位置）を設定に含めると、
署名が毎フレーム変化してシミュレータが作り直され、極端に重くなります。

そのため位置は設定から外し、`LiveValueSource`
（時刻を受け取って値を返す純粋関数）としてエンジンへ渡しています。
編集項目のうち `Animation` 型なのは **発射位置 X / Y とターゲット X / Y だけ**です。

### 時刻は固定ステップの格子で管理する

`CurrentTime += delta` のように積算すると、シークのたびに誤差が変わって
同じフレームでも違う弾幕になってしまいます。
そこで `CurrentTime = ステップ数 × ステップ幅 + 端数` という形で常に再計算し、
**どこへシークしても同じ結果**になることを保証しています。

`EngineTests.cs` にこの性質を検証するテストがあります。

### ファイル名の整形はプラットフォーム依存 API を使わない

`Path.GetInvalidFileNameChars()` は **OS によって返す文字が違います**
（Linux では `/` と `\0` のみ）。
プリセット名からファイル名を作る処理でこれを使うと、CI（Linux）と実機（Windows）で
挙動が食い違います。そのため Windows の規則を明示的に列挙し、
予約デバイス名（`CON` `NUL` `COM1` …）も回避しています。

### スタブ SDK を同梱する

YMM4 の DLL は再配布できないため、そのままでは Windows + YMM4 の環境がないと
コンパイルすら確認できません。
`build/ymm4-stubs/` に**公開 API のシグネチャだけを模したスタブ**を置くことで、
Linux / CI 上でも `dotnet build` による検証ができます。

> スタブはあくまで型合わせ用です。実際の動作確認は必ず YMM4 上で行ってください。

## 開発への参加・引き継ぎ

### 開発を始める

```bash
git clone https://github.com/SCPgamerscp/Ymm4-Danmaku-Plugin.git
cd Ymm4-Danmaku-Plugin

# Windows 以外でも、ここまでは動く
dotnet test tests/Ymm4DanmakuPlugin.Core.Tests/Ymm4DanmakuPlugin.Core.Tests.csproj
dotnet build src/Ymm4DanmakuPlugin/Ymm4DanmakuPlugin.csproj -p:UseYmm4Stubs=true
```

### どこを触ればよいか

| やりたいこと | 触るファイル |
|:---|:---|
| 弾の挙動・物理を変える | `Core/Engine/DanmakuEngine.cs` |
| 新しい発射パターンを足す | `Core/Configuration/Enums.cs`（`PatternKind`）+ `Core/Engine/PatternEmitterBehavior.cs` |
| 新しい弾の形を足す | `Parameters/BulletShape.cs` + `Rendering/BulletSpriteLibrary.cs` |
| 描画の見た目を変える | `Rendering/DanmakuRenderer.cs` |
| 編集 UI に項目を足す | `Parameters/EmitterParameter.cs` / `Parameters/DanmakuShapeParameter.cs` |
| 同梱プリセットを足す | `Core/Presets/PresetLibrary.cs` |
| 外部データ形式を足す | `Core/Importers/` に `IDanmakuImporter` 実装を追加 |

### 変更時のお願い

1. **コアに置けるロジックはコアに置く** — そうすればテストが書けます
2. **テストを追加する** — とくに決定論性を壊す変更は必ずテストで守ってください
3. **設定レコードに毎フレーム変わる値を入れない** — 前述の理由で性能が壊れます
4. 提出前に以下が通ることを確認してください

```bash
dotnet test tests/Ymm4DanmakuPlugin.Core.Tests/Ymm4DanmakuPlugin.Core.Tests.csproj
dotnet build src/Ymm4DanmakuPlugin/Ymm4DanmakuPlugin.csproj -p:UseYmm4Stubs=true
```

### 動作確認の手順（YMM4 実機）

自動テストでは検証できない項目です。

- [ ] プラグインが読み込まれ、図形の種類に「東方風弾幕」が出る
- [ ] プリセットを適用すると弾幕が変わる
- [ ] タイムラインを前後にシークしても、同じフレームでは同じ絵になる
- [ ] キーフレームで発射源が動く
- [ ] プレビュー上の制御点をドラッグして位置が変わる
- [ ] 加算合成・グローが正しく光る
- [ ] ユーザー指定画像が弾として描かれる
- [ ] 効果音チャンネルを合わせると発射音が鳴る
- [ ] ピッチ変調で音が単調にならない
- [ ] 最大弾数を増やしてもプレビューが実用的な速度で動く
- [ ] プロジェクトを保存・再読み込みして設定が復元される
- [ ] 動画として書き出した結果がプレビューと一致する
